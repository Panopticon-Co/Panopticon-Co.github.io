Architecture

Three zones, one-way boundaries

Managed endpoints send telemetry to the Manager control plane. The Manager runs detection, stages responses and dispatches only what has been authorized. Analysts work through the console. Nothing in the detection path can execute anything on a host.

System overview

Running components and trust boundaries

Event flow

Ingest fast, detect asynchronously, act only on authorization

An agent posts a batch to POST /api/v1/ingest (or a v2 endpoint-record route). The Manager commits it to its SQLite WAL store and answers immediately; it never makes the agent wait for detection.

A detection worker claims pending events in bounded batches under a lease, runs them through the vendored detection engine, writes alerts and incidents, and stages any response recommendation as PENDING.

An analyst authorizes or rejects the staged action through the console. Authorized commands are queued; the agent picks them up on its next poll, optionally acknowledges, executes after verifying the target, and posts a typed result.

Two read-only collections are the only actions that may skip analyst approval.

Response actions

Seven actions, two tiers, no exceptions

The vocabulary is closed in the contracts, the response engine and the Manager. An action outside it is rejected, and anything unrecognized falls to the stricter tier — never to auto-run.

ActionWhat it doesTier
COLLECT_PROCESS_INFOCollect details of a target process.AUTO_SAFE
COLLECT_NETWORK_CONNECTIONSCollect the endpoint's current network connections.AUTO_SAFE
COLLECT_FILECollect approved file evidence. No path allowlist exists yet, so it is not auto-safe.ANALYST_APPROVAL
QUARANTINE_FILEMove a file out of reach on the endpoint.ANALYST_APPROVAL
KILL_PROCESSTerminate a process identified by PID and start time, so a recycled PID is refused.ANALYST_APPROVAL
ISOLATE_HOSTBlock network traffic except the Manager channel (Windows Filtering Platform on Windows, a privileged isolation helper on Linux).ANALYST_APPROVAL
RELEASE_HOST_ISOLATIONLift a previous isolation.ANALYST_APPROVAL

Source: response_engine/policy.py. Kill, isolate and release are locked decisions that never auto-fire, regardless of severity.

Lifecycle

Every response is a state machine

Legal transitions are enforced in one place, the response engine. Terminal states have no way out, and any non-terminal state can expire if its window lapses.

PENDING→AUTHORIZED→DISPATCHED→ACCEPTED→ SUCCEEDEDFAILEDREJECTEDINDETERMINATE

Also: CANCELLED (from pending or authorized) and EXPIRED (from any non-terminal state). An agent may skip the optional accept step and report an outcome directly from DISPATCHED.

Boundaries

A polyrepo on purpose

Agents never import engine code, and engines never read agent source. The detection and response engines are vendored into the Manager as pinned submodules and run in-process; they have no network surface of their own.

The detection engine knows nothing about the response engine — its recommendation is just a shape the response engine knows how to translate.
